# STM32 MeteoStation

A compact weather station based on the **STM32F103** microcontroller.

The project measures environmental parameters, processes the collected data and displays the results on an OLED display. The firmware is written in C and uses direct register-level configuration for the STM32 peripherals.

## Features

* Temperature measurement
* Atmospheric pressure measurement
* Relative humidity measurement
* UV index measurement
* Real-time clock using the STM32 RTC
* Zambretti weather forecast
* Two OLED display pages
* Historical weather data storage
* Button-controlled page switching
* Cooperative task scheduler
* 1 ms system tick generated by TIM2

## Hardware

### Main components

* STM32F103
* BME280
* SSD1306-based OLED display
* UV sensor
* External 32.768 kHz crystal
* User button
* Status LED

### Pinout

| MCU pin | Function            | Device             |
| ------- | ------------------- | ------------------ |
| PA0     | User button / EXTI0 | Button             |
| PA1     | ADC input           | UV sensor          |
| PB2     | Status LED          | LED                |
| PB6     | I2C1 SCL            | I2C bus            |
| PB7     | I2C1 SDA            | I2C bus            |
| PC14    | LSE input           | 32.768 kHz crystal |
| PC15    | LSE output          | 32.768 kHz crystal |

The BME280 and OLED display share the I2C bus.

## Peripheral Configuration

### System Clock

The STM32F103 uses an external HSE oscillator and runs at **72 MHz**.

The clock tree is configured directly through the STM32 registers.

### TIM2

TIM2 generates a **1 ms system tick**.

The tick is used by the scheduler to execute periodic tasks without blocking the main loop.

### I2C

I2C1 is used for communication with:

* BME280
* OLED display

The peripheral is configured directly through STM32 registers.

### ADC

ADC1 is used to read the analog output of the UV sensor.

The corresponding GPIO is configured as an analog input and ADC1 performs single-channel conversions.

### RTC

The STM32 internal RTC is used for timekeeping.

The RTC is clocked from the external **32.768 kHz LSE crystal** connected to PC14 and PC15.

The project currently does not use a dedicated external RTC module.

A dedicated RTC module is planned for a future hardware revision and will replace the STM32 internal RTC.

### EXTI

The user button is connected to PA0.

EXTI0 is configured to detect the button press. The interrupt handler changes the display page state.

### OLED

The OLED display uses an SSD1306-compatible controller and communicates over I2C.

The firmware maintains a display framebuffer and transfers it to the display when the screen is updated.

The 8×16 font data is stored in the separate `Fonts` module.

## Software Architecture

The project is divided into several logical layers:

```text
Core
├── Application entry point
├── Scheduler
├── Tasks
└── Shared system data

Drivers
├── ADC
├── BME280
├── Delay
├── I2C
├── OLED
└── TIM2 / RTC

Application
├── Measurement history
├── UV index processing
└── Zambretti forecast

Fonts
└── OLED font data
```

### Core

The `Core` layer contains the application entry point, scheduler, tasks and shared system data.

`main.c` initializes the required hardware and software modules and then continuously runs the scheduler.

### Drivers

The `Drivers` layer contains low-level interfaces for the microcontroller peripherals and connected hardware.

Peripheral configuration is performed directly through STM32 registers.

### Application

The `Application` layer contains higher-level logic operating on the data provided by the drivers.

It currently contains:

* measurement history;
* UV index processing;
* Zambretti forecast calculation.

### Fonts

The `Fonts` module contains the bitmap font used by the OLED driver.

Keeping the font data separate from the display driver keeps the driver focused on display communication and rendering.

## Scheduler

The firmware uses a cooperative time-based scheduler.

Each task has its own execution period:

| Task      | Period |
| --------- | -----: |
| Display   |    1 s |
| BME280    |    1 s |
| UV sensor |    1 s |
| RTC       |    1 s |
| Zambretti |  5 min |
| LED       | 100 ms |

The scheduler uses the TIM2 millisecond tick to determine when each task should run.

The main loop does not use blocking delays for task scheduling.

## Tasks

The task layer connects the scheduler with the application and hardware modules.

### `Task_Display`

Updates the OLED display according to the currently selected page.

The display layout also contains reserved areas for functionality that is not implemented in the current hardware revision.

### `Task_BME280`

Reads:

* temperature;
* atmospheric pressure;
* relative humidity.

The measured values are stored in the shared `MeteoData` structure.

### `Task_UVI`

Reads the UV sensor through ADC1 and updates the UV index.

### `Task_RTC`

Reads the current time from the STM32 RTC and updates the shared system data.

### `Task_Zambretti`

Uses the stored pressure measurements to calculate the Zambretti weather forecast.

### `Task_LED`

Updates the status LED.

## Data Model

The main weather data is stored in the `MeteoData` structure.

```c
typedef struct
{
	int32_t  temp;
	uint32_t press;
	uint32_t humid;
	uint32_t time;
	uint16_t uv;
	uint8_t  zmbr;
} MeteoData;
```

Integer representations are used for sensor values where practical.

This avoids unnecessary floating-point storage in the shared application data.

## Measurement History

Recent measurements are stored in a circular buffer.

The history is used by the Zambretti algorithm to provide the required historical pressure data.

The buffer stores complete `MeteoData` structures.

The current configuration stores one measurement every five minutes, providing a three-hour history.

## Zambretti Forecast

The project implements the Zambretti weather forecasting algorithm.

The calculation uses atmospheric pressure data collected by the weather station.

The calculation consists of:

1. Converting station pressure to sea-level pressure.
2. Using the stored pressure measurements.
3. Calculating the Zambretti forecast index.
4. Storing the resulting index in `MeteoData`.

## Display

The OLED interface currently contains two pages.

### Page 0

Displays:

* current time;
* temperature;
* atmospheric pressure;
* relative humidity.

A reserved area is provided for the date, which is not implemented in the current version.

### Page 1

Displays:

* UV index;
* Zambretti forecast index.

Additional display areas are reserved for functionality planned for future hardware revisions.

## Build and Flash

The project targets the **STM32F103** family.

The firmware can be built using an ARM Cortex-M3 compatible embedded C toolchain and programmed using an appropriate SWD programmer/debugger.

## Current Version

This repository contains the first hardware revision of the project.

The current version uses:

* the STM32 internal RTC;
* an external 32.768 kHz crystal for LSE;
* BME280 for temperature, pressure and humidity;
* an analog UV sensor;
* an SSD1306-compatible OLED display.

Some display areas are intentionally reserved for features that require additional hardware.

## Future Hardware Revision

The next hardware revision is planned to introduce a dedicated **DS3231 RTC module** and an **anemometer**.

The DS3231 will replace the STM32 internal RTC as the primary real-time clock.

The anemometer will provide wind data required for calculating and displaying additional weather parameters, including apparent temperature.

The current firmware architecture leaves room for these extensions without changing the overall application structure.

## Limitations

The current version intentionally keeps the implementation simple.

* No centralized error-handling system.
* Peripheral drivers use direct register access.
* The scheduler is cooperative.
* Sensor and peripheral failures are not handled by a centralized error-management layer.
* The current version does not implement wind measurement.
* The current version does not implement apparent temperature.
* The current version does not implement date display.
* The current version does not use the DS3231 module.
